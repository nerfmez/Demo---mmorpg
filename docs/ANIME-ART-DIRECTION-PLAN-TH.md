## เป้าหมาย

โลกแฟนตาซีการ์ตูนอนิเมะที่สีสะอาด แสงนุ่ม รูปทรงตั้งใจออกแบบ
ใช้ฉากกลางวันของ Ni no Kuni: Cross Worlds เป็นหลักด้านสีและพืชพรรณ
คงเอกลักษณ์เกมใหม่ มุมสูง 3/4 และสัดส่วนตัวละครปกติประมาณ 6–7 หัว
ภาพอ้างอิงเดิมยังใช้ตัดสินความชัดในระยะเล่นจริง

แหล่งอ้างอิงและการสังเกตอยู่ใน FOLIAGE-REFERENCE-STUDY.md
ภาพเมืองและหน้าเลือกตัวละครของ Ni no Kuni ใช้ศึกษาทรงพุ่มและการจัดกลุ่มสี
ไม่ใช้มุมกล้องหรือสัดส่วนตัวละครของภาพเหล่านั้นเป็นข้อกำหนดใหม่

## ลำดับงาน

### 1. กำหนดต้นแบบต้นไม้และพุ่มไม้

- ต้นไม้ใบกว้างหนึ่งต้น: ลำต้นแตกกิ่งรองรับเรือนยอด กลุ่มพุ่มไม่สมมาตร มีช่องว่าง
- พุ่มไม้หนึ่งแบบ: แตกหลายกิ่งจากฐานกว้าง ยอดสูงต่ำต่างกัน ช่อใบเล็ก ขอบไม่เป็นวงกลมซ้ำ ๆ
- ใช้รูปร่างใหม่แทนผลลัพธ์เดิมที่ผู้ใช้ปฏิเสธ ทั้งก้อนหิน พุ่มดอกไม้ และใบซ้อนเป็นแผ่น
- ทดลองโครงปริมาตรภายในร่วมกับกลุ่มใบ/แผ่นใบที่ออกแบบไว้ ถ้าวิธีนั้นให้ผลดีกว่า
  ไม่ผูกกับข้อจำกัดเดิมว่าใบทุกใบต้องเป็นชิ้นแยกหรือห้ามมีปริมาตรภายใน
- เช็คมุมเกมก่อน แล้วใช้มุมใกล้ตรวจรูปทรงเพิ่มเติม

### 2. ทำฉากตัวอย่างเล็กให้ครบระบบภาพ

ใช้มุมเล็กภายในพื้นที่ทดลองเมือง–ทุ่งเดิม ไม่กระจายอาร์ตใหม่ทั้ง bounds ทันที
ประกอบต้นไม้หนึ่งต้น พุ่มไม้สองกอจากต้นแบบเดียว หินกลุ่มเดียว ถนนดิน หญ้า
ส่วนหน้าบ้านหนึ่งหลัง ตัวละครจริงหนึ่งตัว และมอนจริงหนึ่งตัว

ปรับวัสดุและชุดสีพร้อมแสงในฉากทดลองเดียว:
- หญ้าใช้สีร่วมกับพื้นตรงโคนตามระบบที่ทำไว้ และจัดเป็นหย่อมหนา–บาง
- ดินมีปื้นสีกว้าง รอยสึกอยู่ตามทาง หินมีด้านรับแสงและเงาที่อ่านง่าย
- บ้านใช้ผนังครีม ไม้และหลังคาที่แยกกันชัด ลดลายพื้นผิวซ้ำถี่
- ตัวละคร/มอนใช้สีวัสดุที่ผ่านแสงเดียวกัน ตรวจรูปหน้า มือ ผมและชิ้นส่วนเมื่ออยู่ใกล้
- ถ้าแสงใหม่ทำให้เห็นข้อบกพร่องโมเดล ให้บันทึกและแก้ asset เฉพาะจุด ไม่ถือว่า shader แก้รูปทรงแล้ว

ระบบปัจจุบันใช้แสงร่วมทั้ง View: ชุดแสงทดลองต้องแยกเป็น preview scene/profile
ที่เปิดเฉพาะการตรวจงาน และไม่แก้ค่าการเล่นจริงทั่วแมพเพื่อทดลองพื้นที่เล็ก
คง exposure และกล้องในการเทียบ ปรับแสงอย่างมีเหตุผลเพื่อให้รูปทรงอ่านออก

### 3. Dreamloop และภาพส่งตรวจ

ส่งภาพจาก renderer จริง 3 ภาพ:
1. มุมเล่นจริง เห็นต้นไม้ พุ่มไม้ พื้น บ้าน ตัวละคร และมอนร่วมกัน
2. มุมใกล้ เห็นโครงกิ่ง ช่อใบ เงาภายใน และโคนพุ่ม
3. ก่อน/หลังในตำแหน่ง กล้อง ความละเอียด และช่วงเวลาเดียวกัน ระบุการปรับแสง

ตรวจภาพก่อนส่ง: ไม่มีทรงดอกไม้/แผ่นซ้อน, พุ่มกับต้นไม้รูปทรงต่างกัน,
แสงเงาไม่กลบสี, วัตถุไม่ดูเป็นพลาสติก, ใบไม่กลายเป็น noise จากมุมสูง,
ตัวละคร/มอน/ทางเดินแยกจากกันได้ และรอยต่อหญ้ากับพื้นไม่เห็นเป็นชิ้นแปะ
ต้องบันทึกข้อบกพร่องที่ยังเหลือ ไม่ให้ technical pass เท่ากับ art pass

ตรวจ browser/shader errors และจำนวน draw calls/triangles เทียบฐานเดิม
ก่อนเผยแพร่ให้ผ่านชุดทดสอบตาม AGENTS.md รวมถึง touch/WebKit และ resource lifecycle
เครื่องทดสอบไม่มี GPU จริง จึงห้ามอ้างว่าได้ 60 FPS บน iPad จากผลนั้น
รอผู้ใช้ดูภาพก่อน merge/deploy และก่อนขยายทั่วแมพ

### 4. ขยายเมื่อแนวภาพผ่าน

เมืองและทุ่ง → ป่า → พื้นที่ชุ่มน้ำ/ซากโบราณ → ชายหาด
แต่ละพื้นที่ใช้ชุดสีและรูปทรงเฉพาะภายใต้แสง/วัสดุที่สอดคล้องกัน
ชายหาดคงทราย เปลือกหอย คลื่นซัดกลับ และไม่มีหญ้าหรือดอกไม้บนทราย
แม่น้ำตื้นข้ามได้ตามเดิม ไม่มีต้นสน

### 5. ทำส่วนประกอบอื่นให้เป็นงานชุดเดียวกัน

เมื่อฉากผ่าน จึงปรับภาพไอเทม ไอคอนสกิล เอฟเฟกต์ และกรอบ UI ให้สี/เส้น/วัสดุเข้าชุด
ไอเทมต่างชื่อหรือประเภทต้องมีรูปทรงต่างกันตามคำขอเดิม
ตรวจมอนและตัวละครแต่ละชนิด ไม่เปลี่ยนทุกตัวเป็นทรงน่ารักหรือ chibi
การเปลี่ยน layout/ระบบใช้งานไม่ใช่งานในแผนอาร์ตรอบนี้

## จุดเชื่อมกับโค้ดเมื่อเริ่มทำจริง

- data/art.json: ค่าทดลองและชุดสีอาร์ต
- src/render/art-study.js, environment.js: รูปทรงพืชและการวางฉากทดลอง
- src/render/ground-color.js, grass.js, surfaceart.js: สีพื้น/หญ้าและพื้นผิว
- src/render/toon.js, view.js: ชุดวัสดุ/แสงสำหรับ preview และการตรวจร่วมกับโมเดลจริง
- tests/browser/dreamloop.mjs: ภาพซ้ำมุมเดิมและรายงานสถานะภาพแยกจากเทคนิค

ขั้นถัดไปคือข้อ 1–3 เท่านั้น ยังไม่เริ่มเปลี่ยนทั้งแมพจากการตกลงทิศทางนี้
