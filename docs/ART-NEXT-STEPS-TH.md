# แนวทางพัฒนางานภาพต่อ

เอกสารนี้เป็น handoff สำหรับพัฒนาตัวอย่างงานภาพต่อจาก branch นี้ โดยสรุปสถานะ แนวทางศิลป์ วิธีเปิดดู และลำดับการทำงานที่แนะนำ

## เป้าหมายภาพ

- รักษามุมมอง MMORPG แบบ top-down 3/4 ที่เห็นพื้นที่เล่นชัด ตัวละครยังมีสัดส่วนมนุษย์อนิเมะ ไม่เปลี่ยนเป็น chibi หรือกล้อง third-person
- ใช้ภาพอ้างอิงที่ผู้เล่นเลือกเป็นทิศทาง: โทนแฟนตาซีสดและอบอุ่นแบบภาพวาดอนิเมะ มีผิววัสดุอ่านง่าย และรูปทรงสิ่งแวดล้อมที่ไม่ดูเป็นชิ้นสำเร็จรูปซ้ำ ๆ
- สำหรับต้นไม้และพุ่ม ให้สร้าง silhouette จากมวลพุ่มที่ขอบหยักไม่สม่ำเสมอ ซ้อนและเชื่อมกันอย่างมีทิศทาง หลีกเลี่ยงการเอาใบรูปทรงเดียวกันมาเรียงหรือใช้การ์ดใบไม้ซ้ำจนดูเป็นกอสำเร็จรูป
- ลำต้นต้องอ่านเป็นไม้จริงในภาษารูปทรงของเกม: โคนแผ่เป็นรากค้ำ ลำต้นเรียวขึ้นและแตกกิ่งอย่างมีเหตุผล ใช้สีไม้โทนอุ่นและเส้นรอยผิวเท่าที่ช่วยให้อ่านรูปทรง ไม่ทำให้กลายเป็นเส้นร่างแข็งทั่วทั้งชิ้น
- รักษาความสว่างและความอิ่มสีของพื้นที่เดิมไว้ การปรับรูปทรงต้นไม้ไม่ใช่เหตุผลให้ลดความสว่างหรือเปลี่ยนโทนสีของฉากทั้งหมด

## ขอบเขตการทำงานปัจจุบัน

งานนี้เป็น art study แบบเปิดดูได้โดยเลือก `art=anime` และยังไม่เปลี่ยนเป็นภาพหลักของเกมโดยอัตโนมัติ การทดลองที่เพิ่มเข้ามาจำกัดอยู่ในพื้นที่ตัวอย่างเพื่อให้เปรียบเทียบและแก้ได้โดยไม่กระทบฉากเล่นปกติ

- `data/art.json` เก็บการตั้งค่าตัวอย่าง เช่น ขอบเขต พุ่มไม้ ต้นไม้ และพาเลตสีของลำต้น
- `src/render/anime-study.js` สร้าง geometry และผิวของกลุ่มพุ่ม/ลำต้นสำหรับการศึกษา
- `src/render/environment.js` เลือกวาดตัวอย่างในพื้นที่ study
- `src/render/art-study.js` ประกอบฉากและเครื่องมือสำหรับดูตัวอย่าง
- `src/render/ground.js`, `ground-color.js`, `grass.js` และ `view.js` เชื่อมการแสดงผลพื้น หญ้า และตัวเลือกแสงของตัวอย่าง
- `tests/browser/dreamloop.mjs` มีทางเลือกสำหรับตรวจฉากตัวอย่างและบันทึกภาพ

วัตถุสำหรับจัดองค์ประกอบใน study ใช้เพื่อภาพและการตรวจเท่านั้น อย่านำไปผูกกับ collision, inventory, world save หรือระบบเกมจริงโดยไม่ได้ออกแบบแยกต่างหาก

## ขยายใช้ทั่วแมพ

เมื่อเปิด `art=anime` ตอนนี้ต้นไม้ พุ่ม ลำต้น หิน บ้าน หญ้า และสีพื้นใช้แนวทางใหม่ทั้งแมพ (`inArtStudy()` คืนค่า true ทุกจุด) ไม่ได้จำกัดที่พื้นที่ตัวอย่างอีกต่อไป พื้นนอกพื้นที่ตัวอย่างผสมสีพื้นใหม่ 50% เพื่อให้แต่ละโซนยังมีโทนของตัวเอง สนพ (pine) ยังใช้แบบเดิม ฉากตัวอย่างข้างกระท่อม (`sample`) ยังอยู่ที่เดิม โหมดนี้ยังเป็น opt-in เปิดด้วย query เท่านั้น

วัดในเบราว์เซอร์ software GL (medium, มุมเล่นปกติ): สามเหลี่ยมต่อเฟรมเพิ่มประมาณ 2 เท่าเทียบกับ baseline (เช่น meadow 366k เป็น 710k, forest 472k เป็น 906k, กลางเมือง 622k เป็น 1.36M) ก่อนเปลี่ยนเป็นค่าเริ่มต้น ต้องลดจำนวนสามเหลี่ยมของพุ่ม/ต้นไม้ หรือตรวจบน iPad จริงก่อน

## วิธีเปิดดู

1. ติดตั้ง dependencies ด้วย `npm ci` หากยังไม่ได้ติดตั้ง
2. รัน `npm run dev`
3. เปิดหน้าเกมด้วย query `?fresh=1&seed=9&art=anime`
4. ใช้ `art=baseline` เพื่อเทียบกับการแสดงผลพื้นฐานเดิม ทั้งสองโหมดอาจยังใช้พื้นหรือพร็อพบางส่วนร่วมกัน จึงไม่ใช่ A/B ที่แยกทุกตัวแปร

เมื่อตรวจภาพ ให้ดูทั้งมุม overview และมุมเฉียงใกล้ ๆ ตรวจ silhouette ที่ซ้อนกัน ความต่อเนื่องระหว่างกิ่งกับพุ่ม โคนต้น สีไม้เมื่ออยู่บนพื้นจริง และการแยกพุ่มเตี้ยออกจากทรงพุ่มต้นไม้ ตรวจขนาดตัวอย่างที่ใกล้กับการเล่นจริงด้วย ไม่ตัดสินจากภาพซูมอย่างเดียว

## การตรวจด้วย Dreamloop

สคริปต์อยู่ที่ `tests/browser/dreamloop.mjs` ตัวเลือกที่เกี่ยวข้องอ่านจาก environment variables ได้แก่ `DREAMLOOP_ART_REVIEW`, `DREAMLOOP_STUDY_ONLY`, `DREAMLOOP_STUDY_DETAIL`, `DREAMLOOP_ART_ORBIT`, `DREAMLOOP_TRUNK_REVIEW` และ `DREAMLOOP_PASS` ให้ดูการใช้งานปัจจุบันในสคริปต์และ `docs/DREAMLOOP.md` ก่อนรัน เพราะแต่ละ pass มีจุดประสงค์และผลลัพธ์คนละแบบ

ผลล่าสุดก่อน handoff: build ผ่าน และ Dreamloop pass สำหรับพุ่มทรงหยักกับลำต้นรุ่นล่าสุดผ่านการตรวจทางเทคนิคโดยไม่มี browser/shader errors ภาพ overview รายงานประมาณ 583,800 triangles และ 309 draw calls ในสภาพแวดล้อมตรวจดังกล่าว ตัวเลขนี้รวม shadow rendering และเป็นผลจาก browser/software renderer ไม่ใช่ผล benchmark บน iPad จริง

ผล Dreamloop ยืนยันเพียงว่าเส้นทางเรนเดอร์ทำงานและสร้างภาพได้ ไม่ได้ยืนยันว่ารูปทรงหรือสไตล์ผ่านความเห็นเจ้าของงาน การตรวจ WebKit ยังติดข้อจำกัด system libraries ของสภาพแวดล้อม (GTK4/GStreamer) จึงไม่ควรอ้างว่าผ่าน Safari แล้ว

## ลำดับพัฒนาต่อที่แนะนำ

1. ตรวจภาพ overview และ close detail ของต้นไม้รุ่นปัจจุบัน แล้วแก้ silhouette และจุดต่อระหว่างโคน ลำต้น กิ่ง และพุ่มก่อนเพิ่มรายละเอียดผิว
2. ทำให้พุ่มเตี้ยมีภาษารูปทรงของตัวเอง โดยไม่ย่อทรงต้นไม้ลงมาใช้ซ้ำ ตรวจความหลากหลายจากหลายทิศทางและหลายขนาด
3. ตรวจสีไม้และเส้นผิวจากระยะเล่นปกติ รวมถึงตอนอยู่ติดกับหญ้า พื้นดิน หิน และแสงฉาก รักษาสีฉากให้สว่างสดใสตามทิศทางที่เลือก
4. เมื่อรูปทรงธรรมชาติอ่านได้แล้ว จึงค่อยปรับ blend ระหว่างพื้นหญ้ากับพื้นผิวอื่น และพร็อพของพื้นที่ให้ไปในทิศทางเดียวกัน
5. ส่งภาพมุมเดียวกันก่อน/หลังให้เจ้าของงานตรวจ ก่อนขยายแนวทางไปยังพื้นที่อื่นหรือเปลี่ยนค่าเริ่มต้นของเกม

## ข้อควรระวังในการแก้

- คง art study เป็น opt-in ระหว่างรอการตรวจภาพ อย่าเปลี่ยนค่าเริ่มต้นหรือแสง/กล้องของทั้งเกมเพื่อแก้ตัวอย่างเฉพาะจุด
- อย่ากลับไปใช้ใบทรงเดียวกันเรียงเป็นแถวหรือพุ่มทรงกลมสำเร็จรูป เป้าหมายคือมวลพุ่มที่ขอบหยักไม่ซ้ำกันและ silhouette อ่านชัด
- อย่าแก้ด้วยการเพิ่มรายละเอียดเล็ก ๆ อย่างเดียว หาก silhouette ยังดูเป็นกอใบหรือรูปทรงยังต่อกันไม่เป็นต้นไม้
- ทุกครั้งที่แก้ geometry ให้เปิดภาพที่ Dreamloop บันทึกจริงด้วยสายตาในมุม overview และ detail; log ผ่านอย่างเดียวไม่พอ
- PR #9 เป็นงานภาพเก่าที่ถูกปฏิเสธแล้ว อย่านำมารวม ให้ใช้ branch นี้เป็นงานตัวอย่างปรับปรุงใหม่สำหรับการรีวิว
