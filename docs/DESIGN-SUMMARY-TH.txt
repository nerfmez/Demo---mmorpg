สรุปคอนเซปต์เกม MMORPG + Buildcraft
อัปเดตจากบทสนทนาถึง 27 กันยายน 2026

==================================================
1) เป้าหมายของโปรเจกต์
==================================================

- ทำเกมใหม่ทั้งหมด ไม่ใช้โลก ตัวละคร อาชีพ มอนสเตอร์ หรือชื่อระบบจาก Ragnarok Online / Path of Exile โดยตรง
- ใช้แนวคิดของทั้งสองเกมมาผสมกัน:
  - โครงสร้างเกมหลัก เน้นความเป็น MMORPG แบบ Ragnarok Online
  - ระบบสกิลและการสร้าง Build เน้นความลึกแบบ Path of Exile / Undecember
- เป้าหมายระยะแรกคือ “Demo ที่เล่นได้จริง 1 แมพ”
- ยังไม่จำเป็นต้องล็อกทุกระบบตั้งแต่ต้น ระบบต่าง ๆ สามารถเพิ่ม/ลด/ปรับภายหลังได้
- Demo ต้องแสดงให้เห็นตัวตนของเกมก่อน ไม่ใช่พยายามใส่ระบบทั้งหมด

==================================================
2) แนวทางการเล่นหลัก
==================================================

- เป็น MMORPG มุมมองสูงแบบ 3/4 / ARPG
- ไม่ใช่ Third-person action game
- การต่อสู้ต้องยังให้ความรู้สึกว่าเป็น MMORPG ที่เข้าไปตีมอนใน Field
- ไม่เน้นแข่งว่าใครล้างจอหรือฆ่ามอนได้เร็วที่สุดแบบ PoE endgame
- มอนสเตอร์แต่ละชนิดควรมีตัวตน อ่านพฤติกรรมได้ และมีเหตุผลให้ผู้เล่นจดจำ
- รองรับทั้ง PC และ Mobile
- ระบบควบคุมและ UI ต้องออกแบบให้เล่นได้ทั้งสองแพลตฟอร์ม

==================================================
3) ระบบ Target / Combat
==================================================

- ใช้ Soft Targeting
- ถ้าศัตรูยังอยู่นอกระยะโจมตี จะไม่ล็อกเป้า
- เมื่อศัตรูเข้าระยะโจมตี ระบบจะจับเป้าให้อัตโนมัติ
- ถ้าผู้เล่นเลื่อนเมาส์ / Analog / ทิศทางเล็งไปยังมอนตัวใหม่ ระบบจะเปลี่ยน Target
- ถ้าเป้าหมายออกจากระยะ ระบบปล่อย Target
- ตัวละครไม่วิ่งตามเป้าให้อัตโนมัติ
- Skill แบบพื้นที่สามารถเล็งตำแหน่งได้โดยไม่ใช้ Target Lock
- Positioning ของผู้เล่นยังสำคัญ

==================================================
4) Basic Attack
==================================================

- ไม่มี Basic Attack ที่ล็อกติดตัวละครตลอดเวลา
- การโจมตีธรรมดาถือเป็น “สกิลหนึ่ง”
- สามารถใส่/ถอด/เปลี่ยนออกได้เหมือนสกิลอื่น
- Basic Attack สามารถมี Modifier และ Build ของตัวเองได้
- ผู้เล่นสามารถสร้าง Build ที่ไม่ใช้การโจมตีธรรมดาเลยก็ได้

==================================================
5) Movement Skill / Dodge
==================================================

- Movement Skill แยกออกจากช่อง Combat Skill โดยเฉพาะ
- ไม่ควรแย่งช่องกับสกิลต่อสู้หลัก
- แนวทางที่คุยไว้คือใช้ Cooldown หรือ Charge เป็นหลัก
- Movement Skill แต่ละชนิดควรมีเอกลักษณ์ เช่น Roll, Dash, Leap, Blink
- ระบบ Stamina ยังไม่จำเป็นต้องล็อกตอนนี้

==================================================
6) เป้าหมายของระบบสกิล
==================================================

- ต้องรองรับสายการเล่นหลากหลายตั้งแต่พื้นฐาน
- ไม่ควรออกแบบทุกอย่างโดยถามว่า “อะไรทำ DPS มากที่สุด”
- ต้องรองรับการสร้าง Party เป็นธีมและการเล่นร่วมกันจริง
- ตัวอย่างสายที่ระบบควรรองรับ:
  - Melee
  - Ranged
  - Magic
  - DoT
  - Summon
  - Tank
  - Guard / Barrier
  - Heal
  - Buff / Aura
  - Debuff
  - Control
  - Hybrid

- Build ของคนหนึ่งควรสามารถ Interaction กับ Build ของอีกคนได้
- Party ไม่ควรมีแค่ Tank + DPS + Heal แบบแข็งตัว
- Support และ Tank ต้องมี Gameplay ของตัวเอง ไม่ใช่ยืนกดฮีลหรือรับดาเมจเฉย ๆ

==================================================
7) Skill Core + Skill Mod
==================================================

- Active Skill เป็นแกนหลักของสิ่งที่ตัวละคร “ทำ”
- Skill Mod / Modifier ใช้เปลี่ยนพฤติกรรมของสกิล
- Modifier ควรเน้นเปลี่ยนวิธีเล่น มากกว่าการเป็นแค่ +Damage
- ตัวอย่าง:
  - แตกกระสุน
  - เด้ง
  - ทะลุ
  - สร้างพื้นที่
  - ทิ้งเอฟเฟกต์บนพื้น
  - Trigger
  - เปลี่ยนธาตุ
  - เพิ่ม Party Interaction

- Skill และ Mod มี Tag เพื่อจำกัด Interaction เช่น:
  - Melee
  - Projectile
  - Area
  - Channel
  - Movement
  - Summon
  - Persistent
  - Trigger

- ไม่จำเป็นต้องให้ Mod ทุกตัวใช้กับ Skill ทุกชนิดได้

==================================================
8) การเติบโตของ Skill / Mod
==================================================

- ไม่ใช้ระบบแบบ RO ที่กด Fireball Lv.1 → Lv.10 แล้วต่างกันแค่ตัวเลข
- แนวคิด Skill Growth จาก “ใช้สกิลนาน ๆ แล้วเลเวลขึ้น” ถูกมองว่าน่าสนใจ แต่ไม่ควรเป็นแกนหลัก
- เหตุผลคือจะกลายเป็นการบังคับใช้เวลา และลงโทษผู้เล่นที่อยากเปลี่ยน Build
- แกนหลักควรเป็นการอัป Skill / Mod ด้วยของที่หาได้จากโลกและระบบเศรษฐกิจ
- Skill และ Mod สามารถมี:
  - Level
  - Grade
  - Upgrade
  - Modifier progression
- การอัปสกิลควรใช้ Material / Item / Currency ที่มาจากการฟาร์ม, คราฟ, ซื้อขาย
- ระบบนี้ช่วยให้เกิด Economy หมุนเวียน
- Skill Mastery จากการใช้งานจริงอาจมีได้ภายหลัง แต่ควรเป็นโบนัสเสริม ไม่ใช่กำแพงหลักในการเปลี่ยน Build

==================================================
9) Character Level และ Stat
==================================================

- Character Level ยังมีอยู่
- การอัป Character Level ให้ “Stat Points”
- Stat Points เป็นคนละระบบกับ Job Points
- Stat ใช้เพื่อ:
  - กำหนดคุณสมบัติพื้นฐาน
  - เป็น Requirement ของอาวุธ
  - เป็น Requirement ของ Skill
  - เป็น Requirement ของ Skill Mod / ระดับของ Skill และ Mod

- ตัวอย่าง Stat แบบเดิม เช่น STR / AGI / VIT / INT / DEX สามารถใช้เป็นฐานได้
- รายละเอียดหน้าที่ของแต่ละ Stat ยังไม่จำเป็นต้องล็อกใน Demo
- สิ่งที่ล็อกแล้วคือ “แต้ม Stat มาจาก Character Level”

==================================================
10) Job Level และ Job Tree
==================================================

- Job Level ยังมีอยู่
- Job EXP / Job Level แยกจาก Character Level แบบโครงสร้างของ RO
- Job Level ให้ “Job Points”
- Job Points ไม่ใช้กด Skill Level แบบ RO
- Job Points ใช้เดิน “Job Tree / Passive Network”
- Job Tree แยกจาก Stat อย่างชัดเจน
- แนวทาง Tree ควรอ่านง่ายกว่าต้นไม้ขนาดมหึมาของ PoE และใกล้กับแนว Undecember มากกว่า
- ควรแบ่งสายหลักให้ผู้เล่นมองแล้วเข้าใจว่าแต่ละทางนำไปสู่อะไร

==================================================
11) การเลือก Job
==================================================

- ไม่ต้องเลือก Job ตั้งแต่สร้างตัวละคร
- ให้ผู้เล่นลอง Skill / อาวุธ / Build ก่อน
- เมื่อ Build เริ่มมีทิศทางชัด จึงค่อยเลือก Job
- Job ทำหน้าที่ “ต่อยอด Build ที่ผู้เล่นกำลังเล่น”
- ไม่ใช่ “บังคับ Build ตั้งแต่นาทีแรก”
- จังหวะการเลือก Job ต้องไม่เร็วหรือช้าเกินไป
- คล้ายแนวคิดที่ผู้เล่นเดินเข้าโหนดสายหลัก แล้วค่อยเลือกทิศทางที่เหมาะกับ Build

==================================================
12) Respec
==================================================

- เกมไม่ลงโทษผู้เล่นที่อัปผิดสายหนัก
- สามารถใช้เงินในเกมรีแต้มได้
- ไม่ต้องใช้ของหายาก
- ไม่ต้องจ่ายเงินจริง
- เป้าหมายคือสนับสนุนให้ผู้เล่นทดลอง Build
- ความยากควรอยู่ที่ “คิดว่าจะสร้าง Build ยังไง” ไม่ใช่ “กลัวกดแต้มผิด”

==================================================
13) ระบบดรอปจากมอนสเตอร์
==================================================

- ไม่เน้นให้มอนสเตอร์ดรอปอาวุธหรือชุดสำเร็จรูปจำนวนมากแบบ PoE
- เน้นแนวทางแบบ RO ที่มอนสเตอร์ดรอปชิ้นส่วน / Material ของตัวเอง
- ตัวอย่าง:
  - หนัง
  - เขี้ยว
  - กระดูก
  - เขา
  - ต่อมพิษ
  - เปลือก
  - Core
  - Crystal
  - Material หายาก

- ของดรอปไม่ควรเป็น “ขยะ NPC” อย่างเดียว
- Material เหล่านี้ต้องนำไปใช้จริงใน:
  - Craft
  - Upgrade
  - Skill / Mod progression
  - Trade
  - ระบบอื่น ๆ ในอนาคต

- Monster Design ควรสื่อ Material ที่มันดรอปได้ด้วยรูปร่าง
  เช่น มอนที่ดรอปเขาควรมีเขาเด่นชัด

==================================================
14) Crafting และ Gear
==================================================

- Gear หลักเน้นการ Craft จาก Material ที่ฟาร์มจากมอน
- อุปกรณ์ที่ Craft ออกมามี “Grade” แบบสุ่ม
- Gear Grade แยกจากระบบ Upgrade / ตีบวก
- ใช้วัตถุดิบคนละประเภทสำหรับ:
  - Craft
  - Grade / Quality
  - Upgrade / Enhancement
  - Option / Affix (รายละเอียดค่อยออกแบบต่อ)

- Gear ที่ Craft ได้สามารถมี Option แตกต่างกัน
- Material จากมอนสามารถมีอิทธิพลต่อแนว Option ของอุปกรณ์ได้
- Crafting จึงเป็นส่วนหนึ่งของ Buildcraft และ Economy

==================================================
15) Economy
==================================================

วงจรที่ตกลงกันไว้โดยรวม:

Monster
→ Material
→ Craft / Skill Upgrade / Mod Upgrade / Trade
→ Gear / Skill / Build แข็งขึ้น
→ ไปพื้นที่ยากขึ้น
→ ได้ Material ใหม่

- ผู้เล่นที่ไม่ Craft ก็ยังมีบทบาทโดยเป็นคนฟาร์ม Material ขาย
- ผู้เล่นที่ชอบ Craft สามารถซื้อ Material มาผลิตของ
- ระบบควรทำให้ผู้เล่นใหม่และผู้เล่นเก่ายังมีเหตุผลซื้อขายของร่วมกัน
- Material ระดับต้นไม่ควรถูกทำให้ไร้ค่าอย่างรวดเร็วเมื่อมี Content ใหม่

==================================================
16) แนวทาง Theme / World
==================================================

ธีมชั่วคราวที่คุยกัน:

“Fantasy Frontier”

- โลกแฟนตาซีที่มนุษย์กำลังกลับเข้าไปสำรวจและตั้งถิ่นฐานในพื้นที่ที่ธรรมชาติและพลังลึกลับยึดคืน
- ไม่จำเป็นต้องเริ่มจากโลกกำลังแตกหรือจอมมาร
- ผู้เล่นเป็นนักเดินทาง / นักสำรวจ / ผู้แสวงหาโอกาส
- เหตุผลที่ผู้เล่นจำนวนมากอยู่ในพื้นที่เดียวกัน:
  - วัตถุดิบ
  - มอนสเตอร์
  - ซากอารยธรรม
  - Skill / Modifier
  - เส้นทางค้า
  - พื้นที่ใหม่

==================================================
17) Demo 1 Map
==================================================

เป้าหมายปัจจุบันคือทำ 1 แมพที่เล่นได้จริง

แนวคิดพื้นที่:
- เมืองชายแดนขนาดเล็ก / Settlement
- ทุ่งหญ้า
- ป่า
- แม่น้ำ / พื้นที่ชุ่มน้ำ
- ซากโบราณ
- พื้นที่ลึกที่อันตรายขึ้น

แมพเดียวควรให้ความรู้สึกว่ามี Journey:
เมือง / จุดปลอดภัย
→ ธรรมชาติ
→ พื้นที่อันตรายขึ้น
→ ซากลึกลับ / Boss หรือจุด climax ของ Demo

ยังไม่จำเป็นต้องมีระบบ Endgame, Raid, PvP, Guild ฯลฯ ใน Demo

==================================================
18) Art Direction ที่ตกลงล่าสุด
==================================================

ภาพอ้างอิงที่ต้องยึดเป็น “Base Style” คือภาพอนิเมะที่มี:
- ตัวละครสัดส่วนปกติประมาณ 6–7 หัว
- ไม่ Chibi
- Anime Cel-shaded
- สีสดแต่ไม่ pastel/cozy จ๋า
- ฉากแฟนตาซีที่อ่านง่าย
- มีความเป็นเกมจริง มากกว่าภาพประกอบ
- คุณภาพและรายละเอียดอยู่ในระดับที่เกมอินดี้สามารถทำจริงได้
- ไม่ต้องสวยเนี้ยบหรือจริงจังระดับ AAA
- มอนไม่ควรเป็นตุ๊กตาน่ารักเกินไป
- โลกยังมีความเป็นธรรมชาติและแฟนตาซี

สิ่งที่ต้องเปลี่ยนจากภาพอ้างอิง:
- เปลี่ยน “มุมกล้อง” ให้สูงขึ้นแบบ ARPG / Top-down 3/4
- เห็นพื้นที่รอบตัวมากขึ้น
- ลดความรู้สึกแบบ Third-person action

สิ่งที่ “ไม่ควรเปลี่ยน”:
- Art Direction
- สัดส่วนตัวละคร
- ความเป็น Anime
- Mood และโทนภาพโดยรวม

หลักสำคัญ:
“เปลี่ยนมุมกล้อง ไม่เปลี่ยนสไตล์”

==================================================
19) สิ่งที่ยังไม่ล็อก
==================================================

เรื่องต่อไปนี้ยังเปิดไว้และปรับภายหลังได้:
- จำนวน Combat Skill
- จำนวน Mod ต่อ Skill
- Stat แต่ละตัวให้โบนัสอะไรละเอียดแค่ไหน
- Character Level cap
- Job Level cap
- จำนวน Job
- ชื่อ Job
- จำนวนโหนดใน Job Tree
- ระบบ Skill Grade แบบละเอียด
- ระบบ Gear Grade แบบละเอียด
- Rarity
- สูตร Craft
- Fail / Success ของ Upgrade
- PvP
- Guild
- Raid
- Endgame
- Monetization
- โครงเนื้อเรื่องเต็ม
- ชื่อเกมจริง

==================================================
20) หลักการออกแบบที่ควรรักษา
==================================================

1. ระบบหลักต้องยังรู้สึกเป็น MMORPG มากกว่า ARPG แบบ PoE
2. ความลึกของ PoE นำมาใช้กับ “Skill / Mod / Buildcraft” เป็นหลัก
3. ผู้เล่นต้องสามารถทดลอง Build ได้ง่าย
4. ไม่ลงโทษการกดแต้มผิดหนัก
5. ไม่ออกแบบทุก Build เพื่อแข่ง DPS อย่างเดียว
6. Party และ Build ของผู้เล่นหลายคนต้องทำงานร่วมกันได้
7. Monster Drop ต้องมีคุณค่าและหมุนกลับเข้า Economy
8. Crafting ต้องเป็นส่วนสำคัญของ Gear progression
9. Character Level, Job Level, Skill/Mod progression ต้องแยกหน้าที่กัน
10. Demo ต้องพิสูจน์ “ความสนุกของแกนเกม” ก่อนเพิ่มระบบใหญ่

==================================================
สรุปสั้นที่สุด
==================================================
