# ศึกษาการผสานสกิลกายภาพกับเวท — 2 ตุลาคม 2026

ข้อเสนอ: ควรทดลองทำ ระบบนี้เข้ากับการสร้างบิลของ Frontier และใช้ตัวคอมไพล์สกิลเดิมได้
แต่ผลจากเวทต้องเป็นส่วนเสริมของการโจมตีหลัก มีค่า MP และงบผลเวทแยกชัดเจน
การลดดาเมจเวทครึ่งเดียวไม่เพียงพอ เพราะความถี่ จำนวนเป้าหมาย สถานะ และม็อดยังทบกันได้

สถานะ: เอกสารและแบบจำลองตัวเลขเท่านั้น ยังไม่มีการผสานในเกม การแก้ UI แท็กใน PR เดียวกัน
ใช้ระบบแท็กและการใส่ม็อดเดิม ไม่ได้เปลี่ยนกติกาการต่อสกิล

## แท็กที่ผู้เล่นใช้เลือกม็อด

แสดงป้ายสั้น ๆ บนการ์ดสกิลและม็อด ไม่ต้องอ่านคำอธิบายเพื่อเดาว่าใช้กับอะไรได้

| ป้าย | ID เดิม | ใช้บอกอะไร |
|---|---|---|
| กายภาพ | Attack | ท่าโจมตีที่ใช้พลังโจมตี |
| เวท | Spell | สกิลเวท |
| โปรเจกไทล์ | Projectile | ยิงวัตถุที่เคลื่อนที่และชนเป้า |
| วงกว้าง | Area | มีขอบเขตพื้นที่ |
| ประชิด | Melee | โจมตีระยะประชิด |
| เด้งต่อ | Chain | กระโดดต่อไปยังเป้าอื่น |
| ต่อเนื่อง | DoT | ทำดาเมจเป็นช่วงเวลาต่อเนื่อง |
| พื้นที่คงอยู่ | Persistent | มีพื้นที่ที่อยู่ต่อ เช่น บึงพิษหรือน้ำพุ |
| ควบคุม / ดีบัฟ | Control / Debuff | ชะลอ ลดความสามารถ หรือควบคุมศัตรู |
| การ์ด / ฟื้นฟู / อัญเชิญ / เคลื่อนที่ | Guard / Heal / Summon / Movement | หน้าที่ของสกิล |

ใช้ ID เดิมจาก `data/skills.json` และ `data/mods.json` เป็นหลัก:

- `requiresAll`: ต้องมีครบทุกแท็ก เช่น วงกว้าง **และ** ทำดาเมจ
- `requiresAny`: ต้องมีอย่างน้อยหนึ่งแท็ก เช่น ประชิด **หรือ** โปรเจกไทล์ **หรือ** วงกว้าง
- `excludes`: ห้ามใช้กับแท็กที่ระบุ
- `requiresPersistent`: ต้องมีพื้นที่คงอยู่จริง หรือมีม็อดสร้างพื้นร่วมที่ทำงานอยู่
- แท็กของตัวม็อดแสดงแยกจากแท็กที่มันต้องการ ไม่เอาแท็กที่ม็อดเพิ่มมาปลดเงื่อนไขม็อดอื่น
- ธาตุดาเมจเป็นข้อมูลอีกอย่างหนึ่ง หินปะทุเป็น **เวท + วงกว้าง** แม้ดาเมจเป็นกายภาพ
  และดาบที่เปลี่ยนเป็นน้ำแข็งยังเป็น **กายภาพ + ประชิด** ไม่กลายเป็น Spell

## สกิลใดผสมได้

กฎชุดทดลองแรกต้องผ่านทั้งแท็กและรายการความสามารถที่มีตัวรองรับจริง
แท็กบอกประเภท ส่วนรายการรองรับป้องกันการนำสกิลชนิดใหม่มาต่อได้โดยไม่มีตัวประมวลผล

สกิลหลักต้องมี `Attack + Damage`, ใช้ `power: attack`, เป็นการโจมตีตรง
ชนิด `melee_arc`, `melee_nova` หรือ `projectile` และอยู่ในรายการหลักต่อไปนี้:

| สกิลหลัก | แท็กสำคัญ | เป็นตัวหลักได้ | เป็นเวทเสริมได้ |
|---|---|---|---|
| ฟันกวาด — Slash | กายภาพ · ประชิด | ได้ | ไม่ได้ |
| ใบมีดหมุน — Whirl Blade | กายภาพ · ประชิด · วงกว้าง | ได้ | ไม่ได้ |
| ลูกธนูพราน — Hunter's Shot | กายภาพ · โปรเจกไทล์ | ได้ | ไม่ได้ |

เวทเสริมต้องมี `Spell + Damage`, ใช้ `power: spell`, เป็นการโจมตีตรง
และมีโปรไฟล์ถ่ายทอดไฟ/น้ำแข็ง/สายฟ้าต่อไปนี้:

| เวทเสริม | แท็กสำคัญ | ผลที่ถ่ายทอด |
|---|---|---|
| ลูกไฟ — Firebolt | เวท · โปรเจกไทล์ · ไฟ | แปลงดาเมจบางส่วนเป็นไฟ และถ่ายทอดติดไฟ/พื้นไฟที่อ่อนลง |
| ระเบิดน้ำแข็ง — Frost Nova | เวท · วงกว้าง · ควบคุม · น้ำแข็ง | คลื่นเย็นเล็กบริเวณปะทะและชะลอที่อ่อนลง ไม่ได้ร่ายโนวาเต็มวงรอบตัว |
| สายฟ้าโซ่ — Chain Spark | เวท · เด้งต่อ · สายฟ้า | เปลี่ยนบางส่วนเป็นสายฟ้าและเด้งต่อจำนวนน้อย งบเวทแบ่งให้ทุกเป้าที่เด้ง |

ตารางคู่ที่อนุญาตเมื่อทำตัวประมวลผลครบ (9 คู่):

| สกิลหลัก | ลูกไฟ | ระเบิดน้ำแข็ง | สายฟ้าโซ่ |
|---|---|---|---|
| ฟันกวาด | ฟันไฟ | ฟันคลื่นเย็น | ฟันสายฟ้าเด้ง |
| ใบมีดหมุน | ใบมีดหมุนไฟ | ใบมีดหมุนเย็น | ใบมีดหมุนสายฟ้า |
| ลูกธนูพราน | ธนูไฟ | ธนูปะทะเย็น | ธนูสายฟ้าเด้ง |

ท่า ระยะ และความเร็วหลักมาจากสกิลกายภาพ เวทเสริมให้คุณสมบัติและผลปะทะ
ไม่เรียก `executeSkill()` ของเวทเต็มชุดอีกครั้ง ขนาดคลื่นและผลรองต้องใช้โปรไฟล์กลาง
ตามรูปแบบประชิด/วงกว้าง/โปรเจกไทล์กับธาตุ ไม่สร้างโค้ดและเมนูแยกทั้ง 9 คู่

## ม็อดจากเวทเสริมถ่ายทอดอย่างไร

ตรวจ `modFits()` ของเวทต้นทางก่อน แล้วตรวจรายการความสามารถที่โปรไฟล์ผสานรองรับ
ม็อดที่ไม่รองรับเก็บไว้ในคลัง/ชุดได้แต่ไม่ทำงาน แสดงเหตุผลรายชิ้น ไม่ลบทิ้ง

| โปรไฟล์ | ม็อดที่รับในข้อเสนอชุดแรก |
|---|---|
| ลูกไฟ + สกิลประชิด/หมุน | Burning Ground, Lingering (ต้องมีพื้นไฟร่วม), Life Leech, Knockback |
| ลูกไฟ + ลูกธนู | Split, Pierce, Bounce, Burning Ground, Lingering (ต้องมีพื้นไฟร่วม), Life Leech, Knockback |
| คลื่นเย็นที่จุดปะทะ | Concentrated Effect, Echo, Life Leech, Knockback |
| สายฟ้าเด้งที่จุดปะทะ | Bounce, Life Leech |

- Split/Pierce ของลูกไฟไม่ทำให้ดาบกลายเป็นสกิลยิง ต้องมีโปรไฟล์โปรเจกไทล์จึงถ่ายทอดได้
- Frost Shift ชนกับการเลือกธาตุผสาน ให้เลือกใช้หนึ่งระบบ; มีม็อดเปลี่ยนธาตุที่ทำงานอยู่จะผสานไม่ได้
- Cast on Dodge หรือม็อด Trigger ทุกชนิดไม่ถ่ายทอด ห้ามได้เวทฟรีและห้ามวงจรทริกเกอร์
- Wide Arc, Multistrike, Spiked Ward และ Pack Leader ใส่เวทต้นทางเหล่านี้ไม่ได้ตามแท็กเดิม
  ม็อดของสกิลหลักยังใช้กติกาเดิม แต่การโจมตีซ้ำ/เด้งไม่สร้างงบเวทชุดใหม่
- ผลบวกของม็อดถ่ายทอดเริ่มต้นที่ 50% จากค่ากลาง เช่น `×1.25` เป็น `×1.125`
  แต่โทษ `×0.7` หรือพื้นที่ลด 30% คงเดิม ไม่ลดโทษให้เหลือครึ่ง
- จำนวนใช้การปัดลงหลังรวมทั้งฐานและม็อด: `1 + floor(extraProjectiles × 0.5)`;
  `floor((nativeChain + extraChain) × 0.5)` ไม่ปัดทุกม็อดแยก และไม่เกิดครึ่งเป้าหมาย
- การเพิ่มพื้นที่ถ่ายทอดเป็น **พื้นที่** ครึ่งหนึ่ง ไม่ใช่เอารัศมีเพิ่มครึ่งแล้วอ้างว่าเท่ากัน
  เช่นผลบวกตัวคูณรัศมี `r` ใช้ `sqrt(1 + 0.5 × (r² - 1))`; ผลลบคงเดิม
- ผลพื้นไฟ/การร่ายซ้ำ/ลูกเพิ่มรวมในงบเวทก้อนเดียว หากไม่มีงบเหลือจะไม่สร้างดาเมจเพิ่ม
  ระยะชะลอ ความแรงชะลอ ระยะกระเด็น โอกาสสถานะและอายุสถานะต้องลดด้วย ไม่ลดแค่ดาเมจ

## ทรัพยากร การลงทุน และสูตรทดลอง

ค่าต่อไปนี้คือค่าเริ่มทดลอง ไม่ใช่ค่าที่อนุมัติลงเกม ข้อมูลอยู่ใน
`docs/research/skill-infusion-trial.json` ซึ่งเกมไม่ได้โหลด

| รายการ | ค่าเริ่มทดลอง |
|---|---|
| จำนวนเวทเสริม | หนึ่งเวทต่อสกิลหลัก |
| ช่องที่เสีย | หนึ่งช่องม็อดหลัก เหลือม็อดหลักหนึ่งช่อง; เวทเสริมมีม็อดของตัวเองได้สองชิ้น |
| การใช้สกิลต้นทาง | เวทที่ผสานจะถูกจอง ห้ามลงช่องกดร่ายหรือผสานซ้ำพร้อมกัน |
| พลังท่ากายภาพ | 90% ก่อนคริติคอล/ฟินิชเชอร์ |
| แปลงธาตุ | 30% ของพลังท่าหลัก; ย้ายดาเมจเดิม ไม่เพิ่มดาเมจใหม่จากการแปลง |
| พลังเวทถ่ายทอด | เริ่มที่ 35% และปรับลงเมื่อสกิลหลักออกถี่กว่าเวทต้นทาง |
| ผลสถานะ/พฤติกรรมต้นทาง | เริ่มที่ 50%; CC จำกัดความถี่ตามคูลดาวน์เวทต้นทาง |
| ผลบวกของม็อดเสริม | 50%; โทษคงเดิม |
| งบเวทเพิ่มต่อการใช้หนึ่งครั้ง | ไม่เกิน 25% ของดาเมจหลักก่อนลด; รวมทุกเป้า/ลูก/เด้ง/พื้น/ซ้ำ |
| MP เพิ่ม | `ceil(1 + 0.65 × MP เวทต้นทาง + จำนวนม็อดเสริมที่ทำงาน)` |
| การฝึก/คราฟต์ | ต้องเรียนและพัฒนาทั้งสองสกิลและม็อด ด้วยวัสดุของตัวเอง การจัดชุดไม่ทำลายสกิล |
| รีเควส | ต้องผ่านค่าสถานะของสกิลหลัก เวทเสริม และม็อดที่ต้องการให้ทำงาน ตรวจจาก raw stats |

ให้ `A` = ดาเมจกายภาพที่คอมไพล์ตามปกติก่อนคริ/ฟินิชเชอร์,
`S` = งบดาเมจเวทหลังประเมินม็อดเสริมที่ลดแล้ว,
`Ta/Ts` = คูลดาวน์จริงของสกิลหลัก/เวทต้นทาง:

```text
conversion = 0.30 × (0.90 × A)      # เป็นส่วนหนึ่งของดาเมจหลัก
magicBudget = min(0.25 × A, 0.35 × S × min(1, Ta / Ts))
mainDamage = 0.90 × A
combinedMana = mainMana + ceil(1 + 0.65 × sourceMana + activeDonorMods)
```

สูตรคุมงบเวทไม่ให้ความเร็วโจมตีเพิ่มผลเวทเหนือ 35% ของเวทต้นทางต่อวินาที
ยังต้องแบ่งงบตามจำนวนเป้าที่โดน **ทั้งการใช้หนึ่งครั้ง** ไม่คัดลอกก้อนเดิมให้ทุกเป้า
การแปลงธาตุของดาเมจหลักทำให้แต่ละเป้ารับดาเมจธาตุได้ แต่ไม่ถือเป็นดาเมจเวทเพิ่ม
ไม่เอาบัฟโจมตีและบัฟเวทมาคูณก้อนเดียวกันสองรอบ และไม่ให้ฟินิชเชอร์ขยายงบเวทใหม่
ระบบปัจจุบันใช้ defense เดียวกับทุกธาตุ จึงยังไม่อ้างว่าการเปลี่ยนธาตุทำให้เจาะความต้านทาน

กรณี MP/รีเควสของชุดผสานไม่ผ่าน ต้องแจ้งเหตุผลและไม่จ่ายบางส่วน ผู้เล่นถอดผสานเพื่อกลับไปใช้
ท่าปกติได้ ไม่ให้เปลี่ยนเป็นท่าปกติเงียบ ๆ ขณะคิดว่ากำลังใช้ท่าผสาน

## ผลแบบจำลองจากโค้ดปัจจุบัน

รัน `node scripts/skill-infusion-study.mjs` ได้ 27 กรณี (9 คู่ × Lv10/20/40)
ด้วย Stat Points เท่ากัน ใช้ VIT 20% สายกายภาพลงทุน STR/DEX สายเวทลงทุน INT
และสายผสมแบ่งงบโจมตี 55/45 ใช้อุปกรณ์เริ่มต้น C/+0 ไม่มีออฟชั่นหรือ Job โบนัส
แรงค์สกิลเป็น 2/3/5 ตามเลเวลที่ปลดจริง ไม่ได้จำลองการต่อม็อด สถานะ หรือพื้นที่จริง

ถ้าเอา Frost Nova ที่คูลดาวน์ 6 วินาทีไปออกทุก Slash 0.5 วินาทีโดยลดดาเมจครึ่ง
อัตราดาเมจส่วนเวทจะเป็น **6 เท่า** ของการกด Frost Nova ปกติบนตัวละครเดียวกัน
ส่วน Firebolt ครึ่งแรงบนความเร็ว Hunter's Shot เป็นประมาณ 64% แทนที่จะเป็น 50%
นี่เป็นผลคำนวณเรื่องความถี่ ไม่ใช่ผลเทสต์สกิลผสานที่เล่นได้จริง

ตัวอย่าง Lv20, rank 3, ดาเมจก่อน defense/คริ/คอมโบ, สายดาบ + ลูกไฟ:

| บิล | ดาเมจวินาทีช่วง MP พอ | ดาเมจวินาทีตาม MP ฟื้น | หมายเหตุ |
|---|---:|---:|---|
| ดาบล้วน Slash | 93.23 | 93.23 | การโจมตีนี้ไม่มี MP |
| เวทล้วน Firebolt | 81.80 | 32.77 | ยังไม่รวมติดไฟ/ยิงหลายลูก/ระยะโจมตี |
| ดาบผสานลูกไฟตามสูตรทดลอง | 77.45 | 20.21 | จ่าย 6 MP ต่อท่า; MP ที่เต็มพอราว 14.79 วินาที |

ผลสำคัญ:

- งบดาเมจเวทผ่านสองขอบเขตในทุก 27 กรณี แต่ยังไม่ใช่หลักฐานว่าบาลานซ์เกมแล้ว
- บิลผสมไม่เกินดาเมจช่วงแรกของสกิลกายภาพเทียบในทั้ง 27 กรณี
- 16 กรณีมีดาเมจรวมมากกว่า **ดาเมจเป้าแรก** ของเวทเทียบ โดยเฉพาะ Frost Nova
  ซึ่งเป็นเวทคุมฝูงคูลดาวน์ยาว ตัวเลขนี้ไม่ได้รวมเป้าทั้งวงและ CC จึงใช้ตัดสินว่าบิลผสมเก่งกว่าไม่ได้
- MP ชุดทดลองนี้แพงเกินสำหรับบางคู่ เช่น Slash + Frost Nova ที่ Lv20 เต็ม MP ได้ราว
  5.74 วินาที ต้องทดสอบวิธีคิดค่าใช้เมื่อเกิดคลื่นควบคุม หรือปรับน้ำหนัก MP รายโปรไฟล์ก่อนลงเกม
- ไม่ควรสรุปว่าเวทเหลือ 35% แล้วบิลผสมทั้งชุดจะอ่อนกว่าเมจเสมอ ต้องวัดดาเมจรวม
  พื้นที่ ระยะ CC ความอยู่รอด และการเล่นร่วมกันด้วยงบลงทุนและสถานการณ์เดียวกัน

ผลละเอียดและข้อสมมติอยู่ใน `docs/research/skill-infusion-report.json`

## จุดต่อโค้ดและการทดสอบก่อนเปิดใช้

| ส่วน | งานที่ต้องทำเมื่อสร้างระบบจริง |
|---|---|
| Data | โปรไฟล์ถ่ายทอด, whitelist, mod projection, ค่าใช้ MP และขอบเขตพลัง |
| `core/skills.js` | `infusionFits()` เหตุผลรายข้อ, คอมไพล์เวทเสริมแยกจากหลัก, จองหนึ่งช่องม็อดและตรวจความเป็นเจ้าของ |
| `core/game.js` | จ่าย MP แบบ atomic; งบผสานต่อ original cast; ลูก/ซ้ำ/เด้งใช้ cast ID เดียว; คุม CC และไม่เกิด trigger loop |
| Damage | คำนวณสองส่วนโดยบัฟตรงชนิด, ใช้คริและปัดเศษครั้งเดียว, ไม่ยิง on-hit/ลีช/aggro ซ้ำเพราะแยก packet |
| Save | version 5 พร้อม migration `infusion: null` โดยเก็บม็อดหลักเดิม; migration ปัจจุบันจะทิ้ง field ใหม่ จึงต้องแก้ก่อนใช้ |
| UI | ภายในหน้าจัดสกิลเดิม: เลือกหลัก → เลือกเวทเสริม; แสดงแท็ก เงื่อนไข งบเวท/ม็อดที่ถ่ายทอด และ MP รวมก่อนเลือก |
| Renderer/Lab | โครงท่าหลักเดิมพร้อม layer ธาตุ/ปะทะจากโปรไฟล์กลาง; controls สร้างจากข้อมูล; ศึกษาคลิป gallery ตามกฎ VFX ก่อนทำ |
| Godot | พอร์ตข้อมูลคอมไพล์และ budget/cast ID ตรงกัน ไม่ตัดสินกฎใน renderer |

ต้องทดสอบคู่อนุญาต/ห้ามทุกคู่, จำนวนม็อดและ UID ไม่ซ้ำ, ถอด/สลับ/รีเซ็ตสเตตัส,
ธาตุชนกัน, MP ขาดหนึ่งหน่วยไม่จ่ายและไม่เริ่มคูลดาวน์, ยิงพลาด/ยกเลิก, ตาย/วาร์ป/เปลี่ยนชุด,
combo finisher, 2 repeats, split + pierce + bounce, ground + lingering, CC uptime/บอส,
save migration และการเปิด/กด/ลากบน iPad รวมทั้งมือถือ

เป้าตรวจสมดุล: เวทปกติคงพลังธาตุ ม็อด พื้นที่และ CC เต็มกว่า;
กายภาพปกติคงความประหยัด MP และความต่อเนื่องกว่า; สายผสมได้ความสามารถเพิ่มเติมโดยเสียทรัพยากร
ทดสอบเทียบที่เลเวล/แต้ม/ต้นทุนเกียร์/วัสดุฝึกเท่ากัน ทั้งศัตรูเดียว กลุ่มศัตรู บอสและปาร์ตี้
เริ่มทำคู่ Slash + Firebolt ใน Lab ก่อนขยายโปรไฟล์ที่ผ่านเกณฑ์ ยังไม่เปิดทั้ง 9 คู่โดยอาศัยแค่สูตร

## แหล่งอ้างอิงและขอบเขตของข้อสรุป

ตรวจจากแหล่งทางการวันที่ 2 ตุลาคม 2026:

- [UNDECEMBER: Rune Cast](https://guide.floor.line.games/UD/en_US/detail/1166916576948300323)
  ระบุการเน้น Link Runes ที่เข้ากัน การแสดง DPS รวมผล link และช่องสำหรับ trigger skills
  ใช้เป็นแนวทางให้ UI บอกความเข้ากันและผลชุดจริง ไม่ได้ใช้ยืนยันอัตราลดพลังของ Frontier
- [UNDECEMBER: About Runes](https://guide.floor.line.games/UD/en_US/detail/1166916549917300337)
  อธิบาย Skill/Link Runes และทิศทาง Trigger Link เป็นอีกระบบหนึ่งจากการเปลี่ยนคุณสมบัติการโจมตี
- [PoE2: Content Update 0.3.0](https://www.pathofexile.com/forum/view-thread/3826682)
  ส่วน Elemental Infusion อธิบายบางสกิลสร้าง infusion และบางสกิลใช้เพื่อรับความสามารถเพิ่ม
  นำหลักเรื่องคุณสมบัติจากธาตุมาศึกษา ไม่ได้กล่าวว่า PoE2 มีระบบต่อเวทกับท่ากายภาพแบบที่เสนอที่นี่
- [PoE: Content Update 3.15.0](https://www.pathofexile.com/forum/view-thread/3147479)
  ยกตัวอย่าง trigger supports ที่มี Cost/Reservation Multiplier ต่างกัน ใช้เป็นกรณีศึกษาของราคา
  automation ไม่ใช้ตัวเลขจากแพตช์ปี 2021 เป็นค่าปัจจุบันหรือค่าบาลานซ์เกมเรา

การเลือก 9 คู่ ค่า 35%/50% ขอบเขต 25% และสูตร MP เป็นข้อเสนอของ Frontier
