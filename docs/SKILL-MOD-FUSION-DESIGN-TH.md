# ออกแบบ: จัดระเบียบม็อด/สกิล และระบบผสานสกิล

สถานะ: **เฟส 1 ทำแล้ว** (ดูข้อ 10) · เฟส 2–4 รอทำ · ข้อ 5 ในหัวข้อ 9 ยังรอเจ้าของตัดสิน
ฐานข้อมูลที่วิเคราะห์: `main` @ `aabbcfc` — สกิลต่อสู้ 28, สกิลเคลื่อนที่ 4, ม็อด 34, ช่องสกิล 4, ม็อดต่อสกิล 2

## สรุปสั้น

1. **ม็อด = เปลี่ยนพฤติกรรมข้ามหลายสกิล** ทุกม็อดต้องใส่ได้อย่างน้อย 3 สกิล
   ม็อดที่ใส่ได้สกิลเดียวจะถูกขยายให้ใช้ได้กว้างขึ้น หรือรวมกับม็อดที่คล้ายกัน
   **สกิลพัฒนาได้ 2 ทางเท่านั้น: อัประดับ (แรงขึ้น + ช่องม็อดเพิ่ม) และใส่ม็อด** (เจ้าของตัดสินแล้ว ไม่มีระบบแยกสายสกิล)
2. **กฎใส่ม็อดเหลือแบบเดียว** แทนเงื่อนไข 7 แบบที่มีอยู่ตอนนี้ ผู้เล่นดูแท็กแล้วรู้ทันทีว่าใส่ได้หรือไม่
3. **ระบบผสานสกิล**: ให้สกิล **"ตัวส่ง"** (ลูกธนู ฟัน กระโดด ฯลฯ) พา **"ตัวผล"** (ระเบิดน้ำแข็ง บึงพิษ น้ำพุฮีล ฯลฯ) ไปเกิดตรงจุดที่โดน
   สกิลที่ได้ใช้ 1 ช่อง ตัวผลเกิดทุกครั้งที่โดน (เช่น ทุกลูกของแตกกระสุน) แต่ยิ่งเกิดหลายครั้ง แต่ละครั้งยิ่งเบา
   มีคู่พิเศษที่มีชื่อและเอฟเฟกต์ของตัวเอง
4. แบ่งทำเป็น 4 เฟส แต่ละเฟสเป็น PR แยก และแต่ละเฟสลองใน Lab ได้

## 1. ปัญหาของระบบตอนนี้ (จากข้อมูลจริง)

### 1.1 ม็อดหลายตัวใช้ได้แค่สกิลเดียว

ม็อด 9 จาก 34 ตัวใส่ได้แค่สกิลเดียว ซึ่งจริง ๆ แล้วคือ "อัปเกรดเฉพาะสกิล" ไม่ใช่ม็อด
ผลคือผู้เล่นต้องคราฟต์ม็อดที่ย้ายไปใช้กับสกิลอื่นไม่ได้

| ม็อด | ใส่ได้เฉพาะ |
|---|---|
| เถ้าระเบิด `ash_detonation` | ลูกไฟ |
| ผลึกแตก `shatter` | ระเบิดน้ำแข็ง |
| สายฟ้าหวนคืน `chain_return` | สายฟ้าโซ่ |
| พื้นที่เหนี่ยวรั้ง `binding_field` | บึงพิษ |
| ฮีลส่งต่อ `healing_chain` | ชำระบาดแผล |
| เกราะแตกผลัก `breaking_ward` | โล่เวท |
| โล่หนาม `spiked_ward` | โล่เวท |
| คำสาปแพร่ต่อ `spreading_hex` | คำสาปอ่อนแรง |
| บัฟเป็นวงติดตาม `following_aura` | เสียงคำรามศึก |

### 1.2 บางสกิลแทบไม่มีม็อดให้ใส่

| สกิล | จำนวนม็อดที่ใส่ได้ |
|---|---|
| วงจังหวะรบ, กำแพงผลึก | **0** |
| เสียงคำรามศึก | 1 |
| สกิลเคลื่อนที่ทั้ง 4 ตัว | 1 (ก้าวสั้นถี่) |
| ธารเพลิง | 2 (และเป็นม็อดทั่วไปทั้งคู่) |
| ชำระบาดแผล, คำสาป, อัญเชิญ 2 ตัว, โล่เวท | 3 |

ส่วนม็อดกว้าง ๆ อย่าง เปลี่ยนเป็นน้ำแข็ง / ดูดเลือด ใส่ได้ 18 สกิล และกระแทกกระเด็นใส่ได้ 16 สกิล
ม็อดทั่วไปจึงถูกเลือกซ้ำ ๆ แทนม็อดที่เปลี่ยนวิธีเล่นจริง

### 1.3 กฎใส่ม็อดมี 7 แบบ ผู้เล่นเดาไม่ได้

`requiresAll`, `requiresAny`, `excludes`, `requiresKinds` (ชนิดภายในที่ผู้เล่นมองไม่เห็น), `requiresPersistent`, `requiresElement`, `conflicts`
ตัวอย่าง: กวาดกว้างไม่เข้ากับ "ผ่าแนวหน้า" ทั้งที่ทั้งคู่มีแท็ก Melee เพราะถูกกันด้วย `requiresKinds` ซึ่งไม่แสดงบนหน้าจอ

### 1.4 แท็กปนกันหลายความหมาย

- แท็กบอก **รูปแบบ** (Melee, Projectile, Area) ปนกับ **หน้าที่** (Damage, Heal, Buff) และ **ชื่อเฉพาะ** (Rain, Line, Cone, Warcry, Construct, Target, Cleanse, Counter, Charge)
- แท็ก 13 ตัวมีอยู่ในสกิลเดียว และส่วนใหญ่ไม่มีม็อดหรือพาสซีฟตัวไหนอ่านค่า
- `Earth` (หินปะทุ) ไม่นับเป็นธาตุในโบนัสดาเมจธาตุของ Job Tree ส่วน `Fire`/`Cold`/`Lightning`/`Poison` นับ

### 1.5 จุดเล็กที่เจอระหว่างตรวจ

- เสียงคำรามศึก: คำอธิบายบอก "ดาเมจ +25%" แต่ข้อมูลคือ `damageBuff: 0.18` (แล้วค่อยเพิ่มตามระดับ)
- ลูกเวทพื้นฐาน (`arcane_bolt`, คทา) กับ กระสุนเวทพื้นฐาน (`arcane_shot`, ไม้กายสิทธิ์) ชื่อไทยแทบเหมือนกัน แยกยาก
- ธง `prototype: true` ยังค้างใน 14 สกิล + 19 ม็อด ทั้งที่ทั้งหมดคราฟต์ได้ตามปกติแล้ว

## 2. หลักการ

1. **ม็อดเปลี่ยนวิธีเล่น** ถ้ามีเพิ่มพลังก็ต้องมีข้อแลก (เหมือนตอนนี้)
2. **ม็อดหนึ่งตัวต้องใช้ได้หลายสกิล** (≥ 3) ยกเว้นกลุ่มที่เกมมีสกิลน้อย (อัญเชิญ, ฮีล มีอย่างละ 2)
3. **สกิลพัฒนาได้แค่ อัประดับ + ใส่ม็อด** ไม่มีต้นไม้หรือสายแยกของสกิล เพื่อไม่ให้ระบบซ้อนกันจนปวดหัว
4. **ทุกสกิลต้องมีม็อดให้เลือก ≥ 4 ตัว** ที่ทำงานได้จริง (ไม่ใช่ใส่แล้วไม่มีผล)
5. **กฎใส่ม็อดอ่านจากแท็กที่มองเห็นอย่างเดียว** ไม่มีชนิดภายในที่ซ่อนอยู่
6. **ผสานสกิลต้องอ่านง่าย**: ตัวผลเกิดได้ไม่เกิน 5 ครั้งต่อการร่าย และพลังรวมมีเพดาน ไม่ใช่ระเบิดเต็มจอ (ตามหลัก MMORPG ไม่แข่งเคลียร์จอ)
7. ทุกอย่างอยู่ใน `data/*.json` และ `src/core/` ยังเป็นกฎล้วน พร้อมพอร์ต Godot

## 3. แท็กแบบใหม่: 4 กลุ่ม

ทุกสกิลมีแท็กครบ 4 กลุ่ม หน้าจอแสดงแยกสีตามกลุ่ม

| กลุ่ม | จำนวนต่อสกิล | ค่าที่ใช้ได้ |
|---|---|---|
| **รูปแบบ** (ส่งผลอย่างไร) | 1 | ประชิด `Melee`, กระสุน `Projectile`, สายโซ่ `Chain`, เล็งพื้น `Ground`, รอบตัว `Nova`, ร่ายต่อเนื่อง `Channel`, อัญเชิญ `Summon`, ตัวเอง/พวกพ้อง `Self`, สร้างสิ่งกีดขวาง `Construct`, เคลื่อนที่ `Movement` |
| **รูปทรง** (ถ้ามี) | 0–1 | ฟันโค้ง `Arc`, แนวตรง `Line`, กรวย `Cone`, ค้างบนพื้น `Zone`, ออร่า `Aura` |
| **หน้าที่** | 1+ | `Damage`, `Heal`, `Guard`, `Buff`, `Debuff`, `Control` |
| **ธาตุ** | 0–1 | กายภาพ `Physical`, `Fire`, `Cold`, `Lightning`, `Poison`, `Earth`, `Arcane` |

แท็กเสริมที่ยังมีผลจริงจะเก็บไว้ ได้แก่ `Attack`/`Spell` (เลือกพลังโจมตีหรือพลังเวท) และ `Charge`/`Counter` (กฎการกด)
แท็กชื่อเฉพาะที่ไม่มีระบบไหนอ่าน (`Rain`, `Warcry`, `Target`, `Cleanse`, `Minion` ฯลฯ) จะย้ายไปอยู่ในคำอธิบาย

ส่วน `Area` เดิมจะแยกเป็น `Ground` / `Nova` / `Zone` ตามที่สกิลทำจริง
พาสซีฟที่อ่าน `Area` (เช่น `areaDamagePct`, `areaRadiusPct`) ให้อ่าน "รูปแบบพื้นที่" ใดก็ได้ในสามแบบนี้ ผลรวมเท่าเดิม

> **ที่ทำจริงในเฟส 1:** ยังคง `Area` ไว้เป็นแท็กรวม (พาสซีฟ Job Tree และตัวกรองในคลังยังอ่านอยู่)
> แล้ว **เพิ่ม** แท็กรูปทรงที่ผู้เล่นเห็น: ฟันโค้ง `Arc`, รอบตัว `Nova`, เล็งพื้น `Ground`, ค้างบนพื้น `Zone`, โล่เกราะ `Barrier`
> แท็กชื่อเฉพาะเดิม (`Line`, `Counter`, `Curse`, `Warcry`, `Target` ฯลฯ) ยังอยู่เพราะกฎม็อดใช้แยกรูปแบบ การจัดกลุ่มสีบนหน้าจอเลื่อนไปเฟส 2

### กฎใส่ม็อดแบบเดียว

ม็อดมี 5 ช่องข้อมูล:

```json
"needs":  ["Damage"],                // ต้องมีทุกแท็กในนี้
"on":     ["Projectile", "Chain"],   // ต้องมีอย่างน้อย 1 แท็กในนี้ (ไม่ใส่ = ไม่จำกัด)
"not":    ["DoT"],                   // ห้ามมีแท็กในนี้
"family": "element",                 // ม็อดกลุ่มเดียวกันใส่สกิลเดียวกันได้ตัวเดียว
"grants": ["Cold"]                   // แท็กที่ม็อดนี้ให้ม็อดอื่นในช่องเดียวกันใช้ตรวจ
```

แท็กที่ใช้ตรวจคือ **แท็กของสกิล + `grants` ของม็อดตัวอื่นในช่องเดียวกันที่ใส่ได้อยู่แล้ว** (ตรวจรอบเดียว ลำดับไม่มีผล)
ตัวอย่าง: "เปลี่ยนเป็นน้ำแข็ง" ให้ `Cold` ทำให้ "ผลึกแตก" ใส่ได้ / "ทิ้งไฟบนพื้น" ให้ `Persistent` ทำให้ "ค้างนาน" ใส่ได้
กฎนี้แทน `requiresAll`, `requiresAny`, `excludes`, `requiresKinds`, `requiresPersistent`, `requiresElement` และ `conflicts` ทั้งหมด
กลุ่มที่มีตอนนี้: เปลี่ยนธาตุ `element`, ร่ายอัตโนมัติ `trigger`, เปลี่ยนทางกระสุน `trajectory`, ย้ายตำแหน่งศัตรู `displace`

ข้อความบอกเหตุผลบนการ์ดม็อดจะเป็นภาษาไทยธรรมดา เช่น "ต้องเป็น กระสุน หรือ สายโซ่" / "ใส่ม็อดเปลี่ยนธาตุได้ตัวเดียว"

## 4. ม็อดเฉพาะสกิลเดิม: ขยายหรือรวม

เจ้าของตัดสินแล้วว่า **ไม่มี "แนวทางสกิล"** สกิลพัฒนาได้แค่อัประดับกับใส่ม็อด
ม็อด 9 ตัวที่ใส่ได้สกิลเดียวจึงถูกแก้ให้ใช้ได้กว้างขึ้น:

| ม็อดเดิม | ทำอย่างไร | ใช้กับ (หลังแก้) |
|---|---|---|
| เถ้าระเบิด + ผลึกแตก | รวมเป็น **ระเบิดสถานะ** | ดาเมจทุกสกิลที่ติดสถานะ (เผา/เย็น/เลือดไหล/พิษ) |
| สายฟ้าหวนคืน | รวมเข้า **กระสุนย้อนกลับ** → ชื่อใหม่ "ย้อนกลับ" | กระสุน: บินกลับตามทาง / สายโซ่: เด้งกลับเป้าแรก |
| พื้นที่เหนี่ยวรั้ง | ขยาย | ทุกพื้นที่ค้างบนพื้นที่ทำดาเมจหรือติดผลเสีย (บึงพิษ, คำสาป, ไฟบนพื้นจากม็อด) |
| ฮีลส่งต่อ | ขยาย | ทุกสกิลฮีล (ชำระบาดแผล, น้ำพุฟื้นฟู: ฮีลครั้งแรกเด้งต่อ) |
| โล่หนาม | ขยาย | ทุกสกิลรับ/เกราะ (โล่เวท, ตั้งรับสวนกลับ, กระแทกโล่) |
| เกราะแตกผลัก | ขยาย → "รับแล้วผลัก" | ทุกสกิลรับ/เกราะ: เกราะแตก หรือท่ารับจบ แล้วผลักมอนรอบตัว |
| คำสาปแพร่ต่อ | ขยาย → "ผลเสียแพร่ต่อ" | ทุกสกิลที่ติดผลเสีย (คำสาป, บึงพิษ, ฟันเปิดเกราะ) |
| บัฟเป็นวงติดตาม + พื้นที่เคลื่อนตาม | รวมเป็น **วงติดตามตัว** | พื้นที่ค้างบนพื้นทุกแบบ + บัฟ (คำราม → กลายเป็นวงรอบตัวแบบสำรอง MP) |

ม็อดอัญเชิญ 3 ตัวยังใส่ได้แค่ 2 สกิล เพราะเกมมีสกิลอัญเชิญแค่ 2 ตัว ม็อดฮีลก็เช่นกัน ถือว่ายอมรับได้

## 5. รายการม็อดหลังจัดระเบียบ

### 5.1 ม็อดเดิม: เก็บ / ขยาย / รวม / ย้าย

| ม็อด | การจัดการ | ใช้กับ (หลังจัด) |
|---|---|---|
| แตกกระสุน, ทะลุ, ระเบิดปลายทาง | เก็บ | กระสุน |
| เด้ง | เก็บ | กระสุน, สายโซ่ |
| ทิ้งไฟบนพื้น | เก็บ (เพิ่มแท็ก `Zone`) | ดาเมจ ประชิด/กระสุน/เล็งพื้น/รอบตัว |
| สะท้อนซ้ำ | เก็บ | เล็งพื้น, รอบตัว, ค้างบนพื้น |
| รวมพลัง, กวาดรวมศัตรู | เก็บ | เล็งพื้น, รอบตัว |
| กวาดกว้าง, ก้าวตามคม | เก็บ | ประชิดแบบฟันโค้ง `Arc` |
| ฟันซ้ำ | เก็บ | ประชิด (ไม่รวมสวนกลับ) |
| เปลี่ยนเป็นน้ำแข็ง | เก็บ ตระกูล `element` | ดาเมจที่ไม่ใช่ DoT |
| กระแทกกระเด็น, ดูดเลือด, แผลฉีก | เก็บ | ตามเดิม |
| ค้างนาน | **ขยาย** | ค้างบนพื้น + สิ่งกีดขวาง (กำแพงผลึกได้ด้วย) |
| ฮีลเป็นเกราะ | **ขยาย** | ฮีล + ตัวเอง/พวกพ้อง (รวมโล่เวท) |
| จ่าฝูง, คำสั่งผูกเป้า, พันธะคุ้มกัน | เก็บ (อัญเชิญมี 2 สกิล ยอมให้ต่ำกว่า 3) | อัญเชิญ |
| ร่ายเมื่อหลบ, ร่ายเมื่อรับสำเร็จ | เก็บ ตระกูล `trigger` | ตามเดิม |
| ก้าวสั้นถี่ | เก็บ | เคลื่อนที่ |
| ม็อดเฉพาะสกิล 9 ตัว | ขยาย / รวม | ดูตารางข้อ 4 |

**ระเบิดสถานะ** (`status_burst`): เมื่อโดนเป้าที่มีสถานะจากตัวเรา จะใช้สถานะนั้นทำระเบิดวงเล็กตามธาตุ
ไฟ = ระเบิดเถ้า, เย็น = ผลึกแตก, เลือดไหล = แผลปะทุ, พิษ = ฟองพิษ ใช้ข้อแลกเดิม (ลดฮิตตรง)
ใส่ได้ทุกสกิลดาเมจที่ติดสถานะ ทั้งจากตัวสกิลเองหรือจากม็อดเปลี่ยนธาตุ/แผลฉีก ทำให้เกิดคอมโบ "ม็อดวางสถานะ + ม็อดระเบิด"

### 5.2 ม็อดใหม่ (เติมช่องว่าง)

| ม็อด | ตระกูล | ใช้กับ | ผล (ร่าง) |
|---|---|---|---|
| เปลี่ยนเป็นไฟ | `element` | ดาเมจ ไม่ใช่ DoT | ธาตุไฟ โอกาสติดเผา |
| เปลี่ยนเป็นสายฟ้า | `element` | ดาเมจ ไม่ใช่ DoT | ธาตุสายฟ้า ช็อก: ฮิตถัดไปบนเป้า +12% |
| เปลี่ยนเป็นพิษ | `element` | ดาเมจ ไม่ใช่ DoT | ธาตุพิษ แปลงฮิตตรงบางส่วนเป็นพิษ |
| ขยายวง | — | รอบตัว, ออร่า, ตัวเอง/พวกพ้องที่มีรัศมี | รัศมี +30% ผลลด 10% (วงจังหวะรบ, คำราม, โล่เวท ใส่ได้) |

ผลลัพธ์: ม็อดเดิม 34 ตัว รวมกันเหลือ 31 ตัว (รวม 3 คู่ข้อ 4) + ใหม่ 8 ตัว = **39 ตัว**
เป้าที่จะทดสอบอัตโนมัติ: ทุกม็อดใส่ได้ ≥ 3 สกิล (ยกเว้นอัญเชิญและฮีล) และทุกสกิลมีม็อดที่ทำงานได้จริง ≥ 4 ตัว

### 5.3 ยุบสกิลเวทพื้นฐานเป็นสกิลเดียว

**เจ้าของตัดสินแล้ว** ให้เก็บ `arcane_bolt` (ลูกเวทพื้นฐาน) ไว้ตัวเดียว ใช้ได้ทั้งคทาและไม้กายสิทธิ์ (`requiresWeapon: ["staff", "wand"]`)
ส่วน `arcane_shot` (กระสุนเวทพื้นฐาน) ลบออก

- ตัวเลขใช้ของ `arcane_bolt` ความต่างระหว่างคทากับไม้กายสิทธิ์มาจากค่าอาวุธอยู่แล้ว ต้องตรวจ balance model ของสายไม้กายสิทธิ์อีกครั้ง
- ลบสูตรคราฟต์ `arcane_shot` ออก แล้วตรวจว่า `boar_tusk` ยังมีที่ใช้ (ใช้อีกหลายสูตร)
- เซฟเดิม: ถ้ามี `arcane_shot` ให้เปลี่ยนเป็น `arcane_bolt` ทั้งในคลังสกิลและช่องสกิล ระดับใช้ค่าสูงกว่าของสองตัว ม็อดในช่องคงอยู่
  ถ้าช่องสกิลมีทั้งสองตัว ช่องที่สองจะว่าง และม็อดของช่องนั้นกลับไปคลัง
  ถ้าเคยจ่ายเงินคราฟต์ทั้งสองตัว ไม่คืนค่าคราฟต์ (เป็นสกิลพื้นฐานราคาถูก)
- อัปเดต Skill Lab, ไอคอน, `render/actions.js` และตารางใน `FRONTIER-ACQUISITION.md`

### 5.4 จำนวนช่องม็อด

**เจ้าของตัดสินแล้ว: ยิ่งอัปเกรดสกิล ยิ่งใส่ม็อดได้มากขึ้น**
ร่างตัวเลข (ปรับได้ใน `mods.json` → `slotsByRank`):

| ระดับสกิล | ช่องม็อด |
|---|---|
| 1–2 | 2 (เท่าตอนนี้ เซฟเดิมไม่มีม็อดหลุด) |
| 3–4 | 3 |
| 5 (สูงสุด) | 4 |

สกิลผสานใช้ระดับต่ำสุดของสองสกิลต้นทาง จึงได้จำนวนช่องตามระดับนั้นด้วย
ช่องม็อดสกิลเคลื่อนที่คงไว้ 1 ช่อง (สกิลเคลื่อนที่ยังไม่มีระดับ)
ต้องตรวจใน balance model ว่าม็อดช่องที่ 3–4 ไม่ทำให้พลังพุ่งเกินเส้นที่ `BALANCE-40.md` ตั้งไว้

## 6. ระบบผสานสกิล (รวมสองสกิลเป็นสกิลใหม่)

### 6.1 แนวคิด: ตัวส่ง + ตัวผล

- **ตัวส่ง** คือสกิลที่ "พาไป" มีทิศทาง ระยะ และจุดโดนชัดเจน
- **ตัวผล** คือสกิลที่ "เกิดตรงจุด" เช่น วงระเบิด บึง น้ำพุ คำสาป เกราะ บัฟ กำแพง
- สกิลผสาน = ตัวส่งทำงานตามปกติ เมื่อโดน ตัวผลจะเกิดที่จุดนั้น (ถ้าโดนหลายครั้งดูข้อ 6.3)

| บทบาท | สกิลที่เป็นได้ |
|---|---|
| ตัวส่ง | ฟันกวาด, แทงจุดอ่อน, ฟันเปิดเกราะ, ทุบขัดจังหวะ, ผ่าแนวหน้า, กระแทกโล่, ใบมีดหมุน, ลูกธนูพราน, ชาร์จยิงรุนแรง, ลูกเวทพื้นฐาน, ลูกไฟ, สายฟ้าโซ่, หินปะทุ, ฝนลูกธนู, และสกิลเคลื่อนที่ทั้ง 4 |
| ตัวผล | ระเบิดน้ำแข็ง, หินปะทุ, บึงพิษ, คำสาปอ่อนแรง, น้ำพุฟื้นฟู, กำแพงผลึก, โล่เวท, เสียงคำรามศึก |
| ผสานไม่ได้ | อัญเชิญ 2 ตัว, วงจังหวะรบ (ออร่า), ธารเพลิง (ร่ายต่อเนื่อง), ตั้งรับสวนกลับ, ชำระบาดแผล |

หินปะทุเป็นได้ทั้งสองบทบาท แต่ผสานกับตัวเองไม่ได้

### 6.2 จุดที่ตัวผลเกิด

| ตัวส่ง | ตัวผลเกิดที่ |
|---|---|
| กระสุน | เป้าแรกที่กระสุนแต่ละลูกโดน หรือปลายระยะ/จุดชนสิ่งกีดขวาง |
| ประชิด | เป้าแรกที่โดน **ถ้าฟันพลาด ไม่มีตัวผล** (ตามกฎตรวจระยะ/มุมเดิม) |
| สายโซ่ | ทุกเป้าที่เด้งไปโดน |
| เล็งพื้น / รอบตัว | จุดศูนย์กลางของวง |
| เคลื่อนที่ | จุดที่ไปถึง (ผสานกับสกิลเคลื่อนที่จะใช้ช่องเคลื่อนที่) |
| ตัวผลแบบตัวเอง (โล่เวท, คำราม) | ที่ผู้ร่ายเสมอ แต่เกิดเมื่อตัวส่งโดนเท่านั้น |

### 6.3 เมื่อโดนหลายครั้งในการร่ายเดียว (เจ้าของเลือกแบบ ข)

ม็อดที่เพิ่มจำนวนการโดน (แตกกระสุน, เด้ง, ทะลุ, ฟันซ้ำ, สะท้อนซ้ำของตัวส่ง) **ทำให้ตัวผลเกิดทุกครั้งที่โดน**
แต่ยิ่งเกิดหลายครั้ง แต่ละครั้งยิ่งเบาลง เพื่อไม่ให้แรงเกินและไม่รกจอ:

- เกิดได้ไม่เกิน **5 ครั้ง** ต่อการร่าย และเป้าเดียวกันรับตัวผลได้ครั้งเดียวต่อการร่าย
- พลังรวมของทุกครั้ง = 60% × (1 + 0.25 × (จำนวนครั้ง − 1)) แล้วแบ่งเท่า ๆ กัน
- วงของตัวผลเล็กลงอีก 15% เมื่อเกิดมากกว่า 1 ครั้ง

| จำนวนครั้ง | พลังต่อครั้ง | พลังรวม |
|---|---|---|
| 1 | 60% | 60% |
| 2 | 37.5% | 75% |
| 3 | 30% | 90% |
| 5 (สูงสุด) | 24% | 120% |

ตัวอย่าง: ลูกธนู + ระเบิดน้ำแข็ง + แตกกระสุน 3 ลูก = ระเบิดน้ำแข็งวงเล็ก 3 ลูก ลูกละ 30%

### 6.4 ตัวเลขตั้งต้น (ปรับได้ใน `data/fusion.json`)

| ค่า | สูตรตั้งต้น |
|---|---|
| พลังตัวผล | 60% ของค่าตัวผลปกติ ถ้าเกิดครั้งเดียว (คู่พิเศษ 70%) ดูข้อ 6.3 |
| รัศมีตัวผล | × 0.85 |
| ระยะเวลาตัวผล | × 0.75 |
| คูลดาวน์ | max(ตัวส่ง, ตัวผล) × 1.1 |
| MP | (ตัวส่ง + ตัวผล) × 0.75 |
| เวลาร่าย | เวลาร่ายตัวส่ง + 0.1 วิ (ท่าเตรียมเห็นชัดขึ้น) |
| ข้อกำหนด Stat/อาวุธ | ต้องผ่านของทั้งสองสกิล |
| ระดับ | ระดับต่ำสุดของสองสกิล อัปสกิลต้นทางแล้วสกิลผสานแรงขึ้นเอง |

เกณฑ์ทดสอบสมดุล: ใน balance model ที่เลเวลเดียวกัน พลังต่อช่องของสกิลผสานต้องไม่เกิน **1.15 เท่า** ของสกิลต้นทางที่แรงที่สุด

### 6.5 ม็อดบนสกิลผสาน

สกิลผสานมีช่องม็อดตามระดับ (ข้อ 5.4) เหมือนสกิลปกติ และมีแท็กของทั้งสองส่วน
ม็อดจะไปมีผลกับ **ส่วนที่ตรงแท็ก**:
แตกกระสุนมีผลกับตัวส่ง / สะท้อนซ้ำ ค้างนาน รวมพลัง มีผลกับตัวผล / เปลี่ยนธาตุมีผลทั้งสองส่วน
ม็อดต้องเข้ากับอย่างน้อยหนึ่งส่วนจึงจะใส่ได้

### 6.6 การได้มาและการเลิกผสาน

- ทำที่โต๊ะคราฟต์ แท็บ **ผสานสกิล** ต้องมีทั้งสองสกิล และทั้งคู่ต้องอยู่ระดับ 2 ขึ้นไป
- ค่าผสาน: Skill Crystal 1 + วัตถุดิบอัปของทั้งสองสกิลอย่างละ 2 + ทอง 60 (ใช้วัตถุดิบเดิม ไม่เพิ่มดรอปใหม่)
- สกิลต้นทางยังใช้แยกได้ตามปกติ ถ้าใส่ทั้งตัวต้นทางและตัวผสานก็ใช้ 2 ช่อง
- เลิกผสานได้ฟรี แต่ไม่คืนวัตถุดิบ

### 6.7 คู่พิเศษ (มีชื่อ เอฟเฟกต์ และลูกเล่นของตัวเอง)

คู่อื่นที่ไม่อยู่ในตารางใช้ชื่ออัตโนมัติ "ตัวส่ง · ตัวผล" และเอฟเฟกต์ประกอบจากของเดิม

| ตัวส่ง + ตัวผล | ชื่อ | ลูกเล่นพิเศษ |
|---|---|---|
| ลูกไฟ + หินปะทุ | อุกกาบาตเพลิง | ลูกไฟตกจากฟ้าพร้อมวงเตือน หินที่ปะทุติดไฟ |
| ลูกธนูพราน + ระเบิดน้ำแข็ง | ศรเหมันต์ | เป้าหลักโดนแช่ช้าแรงขึ้น |
| สายฟ้าโซ่ + คำสาปอ่อนแรง | โซ่คำสาป | คำสาปติดทุกเป้าที่โซ่เด้ง และคำสาปไม่ลดพลังตามจำนวนครั้ง (เฉพาะคู่นี้) |
| กระโดดทุ่ม + ระเบิดน้ำแข็ง | ลงพื้นเยือกแข็ง | สกิลเคลื่อนที่ผสาน ใช้ช่องเคลื่อนที่ |
| ใบมีดหมุน + บึงพิษ | พายุพิษ | บึงพิษเล็กเกิดตามตัวขณะหมุน |
| กระแทกโล่ + โล่เวท | โล่สะท้อน | กระแทกโดนแล้วได้เกราะ เกราะแตกผลักมอน |
| ลูกธนูพราน + น้ำพุฟื้นฟู | ศรน้ำพุ | ยิงน้ำพุไปช่วยเพื่อนแนวหน้าจากระยะไกล (เล่นร่วมปาร์ตี้) |
| ฟันกวาด + เสียงคำรามศึก | ฟันปลุกใจ | คอมโบครั้งที่ 3 ปล่อยคำราม |
| ชาร์จยิงรุนแรง + กำแพงผลึก | ศรผลึก | ลูกศรปักแล้วตั้งกำแพงที่จุดตก |

เอฟเฟกต์ของคู่พิเศษทำตาม `docs/VFX-REFERENCE.md` และตรวจใน Skill Lab ก่อนเข้าเกม

### 6.8 Skill Lab

- เพิ่มตัวเลือก **ผสาน** ใน Lab: เลือกตัวส่ง + ตัวผล แล้วดูตัวอย่างโดยใช้ adapter เดิมต่อกัน
- ใช้หน้าปรับเอฟเฟกต์ที่สร้างอัตโนมัติจาก `combat-fx.json` ตามเดิม คู่พิเศษมี profile แยก
- มีลิงก์ "ทดลองในเกม · ไม่บันทึก" ที่ให้สกิลผสานทุกคู่สำหรับลองเล่น
